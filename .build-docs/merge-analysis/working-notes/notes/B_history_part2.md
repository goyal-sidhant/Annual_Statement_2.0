### Plain-English glossary (terms used below)

- **Commit** - one saved change in the project history. **Diff** - the exact lines added/removed.
- **PyQt5 / Qt** - the desktop-window toolkit B uses since c258047. **Widget** - any on-screen
  element (button, text box, panel). **View** - one tab's screen code. **Controller** - code that
  runs a job (scan, processing, extraction) and reports back to the screen.
- **Signal / slot** - Qt's "this happened, now run that" wiring between parts of the program.
- **Worker thread** - a second line of execution, so long jobs do not freeze the window.
- **QSS stylesheet** - Qt's CSS-like rules for colours and styles. An **application stylesheet**
  applies everywhere; a **widget stylesheet** is set on one widget and also applies to everything
  inside it, and wins over the application stylesheet where they conflict.
- **objectName** - a label given to a widget so a stylesheet rule like `QPushButton#success` can
  target it.
- **Splitter** - a draggable divider between two panels. **Scroll area** - a panel that scrolls.
- **Collapsible card** - a panel whose header can be clicked to hide/show its contents.
- **Tree view** - a list whose rows can have child rows (here: client folder -> version folders).
- **Glob** - a file-name wildcard search such as `ITC_Report_*.xlsx` (`*` = anything).
- **Lock file `~$...`** - the small hidden file Excel creates next to a workbook while it is open.
- **File signature** - the first bytes of a file that identify its true type: `PK\x03\x04` is a
  ZIP container (.xlsx/.xlsm); `D0 CF 11 E0` is the old OLE format (.xls).
- **stat** - asking the operating system for a file's size and dates (one round-trip each time;
  slow on network shares).
- **Variation** - B's word for a file the scan could not accept or could not recognise; shown as a
  count in the scan summary.
- **Run history** - B's JSON file `~/.gst_organizer/run_history.json` (per user, per PC) that
  remembers past processing and extraction runs.
- **Level 1 / Level 2 / Version / Level 4 folders** - B's output tree:
  `<target>/Annual Statement-DDMMYY HHMM/` (Level 1) -> `<client>-<state code>/` (Level 2) ->
  `Version-DDMMYY HHMM/` (version folder, holds the ITC and Sales reports) -> category folders such
  as `GSTR-3B Exports (<client>)` (the "Level 4" folders). (utils/constants.py:81-90, READ)
- **Dead code** - code that nothing calls. **Stub** - a fake module I wrote so Windows-only code
  (pywin32) could be imported on Linux for testing.
- **Offscreen** - running Qt windows with no screen, for tests and screenshots.
- **HTML insertion** - text added to a log box as web markup, so `<`, `>`, `&` in a file name are
  read as markup, not shown literally.

     valid Excel', 'size'}` and returns (lines 183-191).
   - Opens the file and reads 8 bytes; if they start neither with `PK\x03\x04` nor
     `\xd0\xcf\x11\xe0`: variation `'Invalid or corrupted Excel file'` (lines 194-206). If the open
     itself raises `OSError`: variation `'Cannot read file: <error text>'` (lines 207-215).
   - Builds the file-info dictionary itself from the one stat (lines 218-226): keys `name`, `path`
     (= `str(file_path)`; old code used `str(path.absolute())`), `size`, `size_formatted`,
     `modified`, `created`, `extension`. The old keys `is_file` and `is_dir` are gone (nothing reads
     them: grep at B HEAD finds them only inside `get_file_info`, utils/helpers.py:131-132 - HIGH).
   - Rest unchanged in meaning: parse the name (line 229), store in `scanned_files` (line 240), add
     to client data if parsed with client and state (lines 243-244), else variation with
     `pattern_expected` (lines 246-252). Only whitespace/comment lines changed there, and
     `file_info.get('size', 0)` became `size`.
- Constants: minimum size **1024 bytes** and the two signatures are the same values that
  `validate_excel_file` used (utils/helpers.py:232, 240-241) - moved, not changed (HIGH, READ).
