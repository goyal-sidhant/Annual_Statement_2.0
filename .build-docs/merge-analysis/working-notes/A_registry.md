# Registry - project A (AnnualStatement_oldv1)

Project A = `goyal-sidhant/AnnualStatement_oldv1`, branch `main`, snapshot HEAD `bf2f1dd` (27-07-2026), a Tkinter desktop program that calls itself "GST File Organizer v3.0". This registry lists every FEATURE (A-F1 ...) and every BUSINESS RULE (A-R1 ...) of project A at that snapshot. Every later audit section, and the later comparison with project B, uses exactly these IDs.

## How to read this registry

- **IDs.** Features are `A-F1` ... `A-F31`, ordered by the user's workflow (start-up, Step 1 Setup, Step 2 Validation, Step 3 Processing, Step 4 Extract, then things that apply everywhere). Rules are `A-R1` ... `A-R157`, grouped in the 16 canonical categories, numbered straight through. Gaps found later (Section 7) will be `A-G1` ...; they are not in this file.
- **Locations** are repository-relative `file:line` at `bf2f1dd` (the line numbers of `/root/merge-scratch/A-copy`, which is identical to the repository). Every location in this file was checked in the code by me (READ). Where an old version matters it is written `path:line@commit`.
- **Commits.** The 12 commits shared by A and B (`edac6a3` ... `47a1492`) are marked "shared - before the split on 30-10-2025". A's later commits are marked "A only (after the split)".
- **READ / RAN.** READ = established by reading the code. RAN = the code was executed on made-up inputs in a scratch copy (never in the repository). "RAN (me)" = I re-ran it for this registry in `/root/merge-scratch/run/REGISTRY-A/` (scripts `check1.py`, `check2.py`); "RAN (TRACE)" etc. = run by the reader whose notes are named. Excel-through-COM parts cannot run on this Linux machine and are always READ. Inferences carry HIGH / MEDIUM / LOW confidence.
- **[GST RULE]** = the code decides a tax figure, which return / table / sheet / cell a figure or file belongs to, a rate, limit, rounding, period, GSTIN/PAN/state-code logic, ITC eligibility or a due date. When in doubt a rule is tagged yes. For these rules this file only says what the code does; it never says whether it is right.
- **TIME-VARYING** = the value can change over time (return or table names, template cell positions, state lists, file-naming conventions, package versions). Such values carry the symbol ⚠ so the author can check them.
- **DEAD** = defined but never used by the program (it may still be used by tests).
- **Client confidentiality.** No client name, GSTIN, PAN, real file name or figure appears here. Examples use `<Client A>`, `<Client B>` and invented names such as `ClientA`. Generic file-name PATTERNS the code recognises are quoted exactly because they are code.

### Plain-English terms used below

- **regex / pattern** (a text-matching rule for file names; `[^-]+` means "one or more characters that are not a hyphen"); **group** (the part of a match that is kept, e.g. the client name).
- **COM** (Windows' way for one program to drive another; here Python drives Microsoft Excel); **pywin32** (the Python package that provides COM: `win32com`, `pythoncom`, `win32api`, `win32gui`, `win32con`).
- **GetActiveObject / Dispatch / DispatchEx** (three ways to get an Excel: grab the one already running, start one but possibly attach to a running one, always start a separate one).
- **openpyxl** (a Python library that reads and writes `.xlsx` files without Excel; when it saves a workbook it drops Power Query).
- **Power Query** (Excel's data-import tool; its queries live inside the workbook in a hidden part called DataMashup; "refresh" re-runs them).
- **Links sheet** (the sheet in the ITC/Sales templates into which the program writes folder paths and file names that the template's queries read).
- **Tk / Tkinter** (Python's built-in window toolkit); **Treeview** (Tk's table widget, the client list); **IntVar** (a Tk variable holding a whole number).
- **thread / worker thread** (a second line of work running beside the window); **daemon thread** (a worker that is killed instantly, without clean-up, when the program exits).
- **mtime** (a file's or folder's "date modified"); **glob** (wildcard file search such as `ITC_Report_*.xlsx`); **stem** (file name without its extension).
- **staging file** (a temporary local copy that is worked on and then copied to its final place); **UNC path** (a network path `\\server\share\...`); **8.3 short path** (an old DOS-style short alias of a long path).
- **JSON** (a plain-text settings format); **current folder / CWD** (the folder a program was started from; a file name with no folder part is created there).
- **find_spec** (a Python check that a module file exists, without loading it); **SendKeys** (pressing keyboard keys by program into whatever window has focus).
- **dead code** (code that nothing in the program ever calls).

## Scope notes (what was deliberately merged or split, and why)

**Features.**
- All 26 items of the canonical feature list exist in A and use the canonical names (A-F1, A-F3 to A-F5, A-F7 to A-F11, A-F13 to A-F17, A-F19, A-F21 to A-F31). Five features were added because A has them and the canonical list does not: A-F2 (main window, title strip, status bar and the close confirmation), A-F6 (maximum client folder name length — a separate user control that shapes folder names), A-F12 (export of the ticked clients to a text file), A-F18 (the Step 4 tab that hosts the extractor, including its folder sync and fallback notice) and A-F20 (Step 4 client/report ticks with the "Last Refresh Status" column).
- Merged into one feature: the Step 2 scan summary text and all selection controls (click, keyboard, Select All / Clear All / Complete Only) into A-F8; Stop, the ETA, the completion box and opening the output folder into A-F17; the "full" hand-over to Step 4 into A-F5; the global tick AND the per-client column into A-F10 (the canonical name says "per-client"; A's global tick overrides it); Re-scan into A-F7; processing modes and backups into A-F13 as the canonical name says; the Setup "EXPECTED FILE NAMES" card into A-F31; the Step 4 wait-time box into A-F21; the offer to open the consolidated workbook into A-F24.
- A-F14 and A-F15 are split (as the canonical list asks) although they share one mechanism in `core/excel_handler.py`; the shared rules (A-R56 to A-R60, A-R96 to A-R101) apply to both.
- A-F26 (error dialogs) is listed with the cross-cutting features as in the canonical order, although in A it only runs inside the Step 4 refresh.

**Rules.**
- One rule per file-name pattern (A-R1 to A-R6) plus one for the matching procedure common to all six (A-R7). The scan filters are split into scope/extension (A-R8), size (A-R9) and signature (A-R10) because they are separate decisions with separate constants.
- One rule per extraction output sheet (A-R74 to A-R82), cells listed inside; the shared reading mechanics are one rule (A-R83). The consolidator's column lookup that cross-wires nine cells is its own rule in category 11 (A-R88) and is cross-referenced from A-R80 to A-R82.
- The ITC and Sales Links maps are one rule each (A-R54, A-R55); the form of the values (A-R56) and the "first file wins" decision (A-R57) are separate because they apply to both maps and are decisions in their own right.
- The whole fixed sequence of refresh waits and retries is one rule (A-R72) because the numbers only make sense together; the key-press method (A-R71) and the success test (A-R73) are separate decisions.
- The state table is one rule listing all 39 entries (A-R21); the fallback for unknown names (A-R22) is separate.
- Every constant, dictionary key or option that is defined but never used has its own ID marked DEAD (A-R13 to A-R16, A-R30, A-R34, A-R37, A-R44, A-R49, A-R50, A-R53, A-R63, A-R70, A-R84, A-R85, A-R92 to A-R95, A-R107, A-R117, A-R130, A-R150, A-R151, A-R153). Never-called helper FUNCTIONS got an ID only where they encode a decision or a constant (date format, unique-name limit, hash method, relative paths, report layouts); dead functions without such a decision (for example `CacheManager.get_cached_value` / `set_cached_value`, `UIHelpers.update_status`, `FileOrganizer.cleanup_on_error` / `get_summary`, the three dead delegators in `gui/main_window.py`) are dead code for Section 2, not rules. `A-R18` and `A-R25` are marked DEAD because their output is computed but never read, although the code itself runs.
- Test-only helpers (`validate_excel_file`, `find_excel_files`, `utils/helpers.py:240-260, 368-373`) repeat exactly the checks of A-R8 to A-R10 and were not given separate IDs.
- `A-R23` and `A-R60` are cross-cutting rules kept so the comparison with B can check that the state code and the "every client gets both reports" behaviour match, even though parts of them appear in other rules.
- The run time stamps are placed in category 6 (A-R33) and not in category 4, because they are clock times used in names, not tax periods; category 4 holds the one real finding about periods (A-R25: none are used).
- Rules tagged [GST RULE] "yes" include several where the tag is conservative (A-R7, A-R12, A-R16, A-R23, A-R28, A-R35, A-R51, A-R56, A-R59, A-R60, A-R73, A-R83, A-R88 to A-R90): they decide which file, cell or figure reaches a report or whether a figure appears. No GST rule is judged here.
- Where an older document disagrees with the code, the disagreement is noted in the feature or rule it concerns (e.g. README "variations tab" in A-F9, design note on the "full" mode in A-F5, help texts in A-F31); the full list is in DOCS.
