**How to read this registry**

- Every location is `file:line` in project B at b0e7d0e (repository-relative). Every location in both tables was checked against the code by reading it (READ). Where a statement says **RAN**, the code was executed on made-up inputs - either by a reader agent (the note is named) or by this task (scripts in `/root/merge-scratch/run/REGISTRY-B/scripts/`, on a copy of the code, `python -B`). Excel-through-COM parts could not be run on this Linux machine and are traced by reading (fake stand-in modules only prove the order of the calls). Confidence words: HIGH / MEDIUM / LOW.
- **[GST RULE]** marks anything that decides a tax figure, which return / table / sheet / cell a figure belongs to, a rate, limit or threshold, rounding, the financial year or period, GSTIN / PAN / state-code logic, ITC eligibility or a due date (when in doubt, tagged). For these the registry only says what the code does; it never says whether it is right. **⚠** marks a value that can change over time (return and table names, template cell positions, state lists, dates) so the author can check it. **TIME-VARYING** = yes means the rule contains such a value.
- **DEAD** = defined but never used. "yes (in practice)" = the code can run but never does with the current configuration or screens; "yes (write-only)" = stored but never read back.
- Client names never appear here; `<Client A>` is a placeholder. File-name patterns the code recognises are quoted exactly because they are code, not client data.
- Notes abbreviations (working notes in `/root/merge-scratch/notes2/`): **CU** B_code_core_utils.md; **PQ** B_code_pq_models_startup.md; **MW** B_code_mainwindow_controllers_theme.md; **VW** B_code_views.md; **DC** B_dead_code_patterns.md; **XL** B_excel_pq_safety.md; **OF** B_outside_files_state.md; **DO** B_docs.md; **LT** B_live_traces.md; **SH** shared_history_12_commits.md; **H1** B_history_part1.md; **H2** B_history_part2.md.

**Plain-English terms used in the tables**

- *Run folder / Level-1 folder*: `Annual Statement-<DDMMYY HHMM>` inside the target folder; *client folder / Level-2*: `<client>-<state code>`; *Version folder*: `Version-<DDMMYY HHMM>` inside the client folder; *category folders*: the three sub-folders of a Version folder.
- *Variations*: the code's word for problem files (unrecognised or invalid).
- *Links sheet*: the sheet in each report template into which the program writes folder paths and file names for the template's Power Query (Excel's built-in data-import feature) to use.
- *COM / pywin32*: the Windows mechanism, and the Python add-on that uses it, by which Python drives Excel. *Dispatch / DispatchEx / GetActiveObject*: three ways of getting an Excel; `GetActiveObject` grabs the Excel already running, `Dispatch` may reuse one, `DispatchEx` always starts a separate one (what the author's Standard 12 asks for).
- *SendKeys*: typing keystrokes into whichever window has the keyboard focus, as if a person pressed them.
- *openpyxl*: a Python library that reads and writes .xlsx files without Excel (it drops Power Query when it saves an existing workbook).
- *Regular expression (regex)*: a text pattern used to recognise file names. *Glob*: a wildcard file search such as `*.xlsx`. *Stem*: a file name without its extension. *mtime*: a file's or folder's "last modified" time.
- *Worker thread*: a background line of work, so the window does not freeze. *Signal*: Qt's message from one object to another.
- *JSON*: a plain-text file format for settings.
