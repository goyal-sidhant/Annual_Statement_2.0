### 6.0 How to read Sections 6 and 7

**What these two sections cover.** Project A (`goyal-sidhant/AnnualStatement_oldv1`, branch `main`, snapshot `bf2f1dd`, 27-07-2026; the Tkinter program that calls itself "GST File Organizer v3.0"). Section 6 lists every unusual situation the code deliberately handles ("edge case" = an input or situation at the edge of what is normal: an empty folder, a missing sheet, a blank value, a duplicate file) and lists every `try/except` block (a `try/except` block is the place where the program catches an error so that it does not stop). Section 7 lists what the code does NOT handle, numbered A-G1 onwards.

**Evidence markers.** Every statement about the code cites `file:line` at `bf2f1dd` (repository-relative; the scratch copy `/root/merge-scratch/A-copy` has the same line numbers). Older code is written `path:line@commit`.
- **READ** = established by reading the code.
- **RAN** = the code was executed on made-up inputs in a scratch copy. "RAN (me)" = re-run for this section on 21-10-2026 in `/root/merge-scratch/run/A-S67/` (scripts `scripts/r1_core.py` … `r7_extractor_scan.py`, outputs `out_r1.txt` … `out_r7.txt`; list in 7.12). Nothing that needs Excel through COM or Windows could run here (Linux, no Excel, no pywin32): those parts are READ only.
- Inferences carry **HIGH / MEDIUM / LOW** confidence. "NOT SURE" always comes with a way to check.

**IDs.** Features `A-F1` … `A-F31` and rules `A-R1` … `A-R157` are the registry's (`/root/merge-scratch/audit/A_registry.md`). Gaps are `A-G1` … `A-G79`, numbered in Section 7 in the order they appear; 7.10 lists them all in one table.

**[GST RULE] and ⚠.** Anything that decides a tax figure, which return / table / sheet / cell a figure or file belongs to, a state code, a period or a rounding is tagged **[GST RULE]**. For these, Sections 6 and 7 only say what the code does; they never say whether it is right. Values that can change over time (table numbers, template sheet names and cell positions, state lists, file-naming conventions of the portal, period texts and financial years used as examples, Excel's keyboard shortcuts, package and Python versions) carry **⚠** so the author can check them.

**Confidentiality.** No client name, GSTIN, PAN, real file name or figure appears here. Made-up names such as "Alpha Test Traders" and `<Client A>` are used; file-name PATTERNS the code recognises are quoted exactly because they are code.

## SECTION 7: EDGE CASES NOT HANDLED (GAPS AND VULNERABILITIES)

### 7.0 How to read this section

Each gap has an ID (A-G1 … A-G79), the place in the code, what happens, how the user notices (or does not), a severity, and the evidence. 7.10 lists all IDs in one table; 7.8 runs the "what would break if…" scenarios for every major feature and points back to these IDs.

**Severity scale used here.**
- **HIGH** — can silently produce wrong figures or wrong files, lose the user's work, damage a workbook, or stop normal use, in situations that happen in ordinary office work.
- **MEDIUM** — wrong, misleading or failed output in plausible but less common situations, or a significant obstacle the user can work around.
- **LOW** — cosmetic, rare, latent (needs a configuration change to bite) or only a maintenance trap.

Severity describes the technical consequence. For anything tagged **[GST RULE]**, only the mechanism is described: whether the rule itself is right is the author's decision. "Which cell is right" in A-G1 and similar items is likewise the author's call.

#### A-G1 — The consolidated Step 4 workbook fills 9 columns from a cell other than the one its configuration names [GST RULE] ⚠

- **Where:** `power_query_extractor/core/data_consolidator.py:137-150` (lookup), fed by `power_query_extractor/core/report_processor.py:581-588` (how values are stored), `power_query_extractor/config/cell_mappings.py:264-278` (field names built as `"<output sheet>_<column>"` with spaces turned into `_`) and `power_query_extractor/config/cell_mappings.py:156-228` (the three affected output sheets).
- **What happens:** for each output column the consolidator first takes the FIRST extracted value whose field name merely CONTAINS the column title (`power_query_extractor/core/data_consolidator.py:141-145`), and uses the exact field name only if that found nothing (`:147-150`). Titles with spaces ("Diff IGST", "IGST Diff", "Table 6J Match" ⚠) never match the underscore field names and fall through to the exact name as configured. The one-word titles "IGST", "CGST", "SGST" of the output sheets "IMS Reco", "Extra In Purchase" and "Extra In GSTR2B" match `GSTR-3B_Difference_Diff_IGST/CGST/SGST` first (the "GSTR-3B Difference" group is the first in the configuration). - **How the user sees it:** not at all — the workbook looks complete; the three sheets repeat the GSTR-3B difference figures client by client.
- **Severity:** HIGH (silent figures taken from cells other than the configured ones, in a delivered workbook).
- **Evidence:** RAN (me r2, made-up marker numbers: "columns OK 13 mismatched 9", each mismatch listed in `out_r2.txt`; RAN VERIFY: same 13 / 9 result on a fresh copy); also RAN (TRACE T4 Part E; XL E3; DOCS exp-3; registry check2.py). ### 7.5 Security concerns

No passwords, tokens or keys exist anywhere in the code (READ, grep); no client data is sent over a network (READ: no `requests`/`urllib`/`socket`/`http` in the source). The concerns are about the user's own data and programs.

#### A-G54 — The program takes over the user's own Excel, hides it and quits it

- **Where:** Step 3: `core/excel_handler.py:123-128` (`GetActiveObject` first — the user's running Excel — then `Dispatch`), `:131-133` (Visible, DisplayAlerts, ScreenUpdating set False), `:238-246` (DisplayAlerts set back to True, then `Quit()` ALWAYS: the guard `if self.excel_app is None` is always true because `excel_app` is set only once, to None, at `:56`).
