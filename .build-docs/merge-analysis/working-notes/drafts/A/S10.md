**Plain-English terms used in this section** (first use explained here once):

- **window / dialog / message box** - a window is a framed area on screen; a dialog is a small window that asks something; a message box is a standard small dialog with an icon, a text and buttons such as OK or Yes/No. **Modal** = it blocks the rest of the program until answered.
- **Tk / Tkinter** (Python's built-in window toolkit) and **ttk** (Tk's "themed" widgets, whose colours come from a shared style table rather than from each widget). **widget** = any single on-screen element (button, label, text box, table). **theme 'clam'** = one of Tk's built-in looks (flat grey-beige).
- **tab / notebook** - a notebook is the container with clickable tab titles ("Step 1" … "Step 4"); a **sub-tab** is a tab inside a tab.
- **Treeview** - Tk's table widget (the Step 2 client table).
- **Entry** (one-line text box), **Spinbox** (number box with small up/down arrows), **Checkbutton** (tick box), **Radiobutton** (round option button, one of a group), **Text / ScrolledText** (multi-line text box, with a scroll bar), **Label** (fixed text), **LabelFrame** (a box with a title written into its border), **Canvas** (a drawing area, used here to make a page scroll), **progress bar**.
- **pack / grid / place** - three Tk ways to position widgets: *pack* stacks them top-to-bottom or side-by-side, *grid* puts them in rows and columns, *place* puts them at fixed pixel coordinates.
- **`command=` vs `.bind('<Button-1>')`** - two ways to connect a button to a function. `command=` runs on a normal click (press and release), is ignored when the button is disabled (greyed out), and can be triggered from the keyboard. `.bind('<Button-1>')` reacts to the raw left-mouse press: it still fires on a greyed-out button and cannot be reached from the keyboard.
- **tooltip** - a small yellow pop-up text that appears when the mouse rests on something.
- **status bar** - the strip at the bottom of a window that shows a one-line message.
- **worker thread** - a second line of work running beside the window so the window stays usable; **UI thread / main thread** - the one that draws the window.
- **debounce** - wait until typing pauses before re-checking.
- **hex colour** - a colour written as `#RRGGBB`, e.g. `#0078D4` (blue).
- **COM / pywin32** - Windows' way for Python to drive Microsoft Excel, and the Python package that provides it.
- **settings file** - `~/.gst_organizer_cache.json` in the user's home folder, where the program remembers paths and choices (A-F27). `~` means the user's home folder (on Windows `C:\Users\<user>`).
- **pip** - Python's own tool that downloads and installs extra packages; **openpyxl** - the Python package that reads and writes Excel files without Excel; **pywin32** - see COM above.
- **UTF-8** - a way of storing text that can hold every character, including emoji; **exit code** - the number a program hands back to Windows when it stops (0 = fine, 1 = failed).
- **ImportError / AttributeError / traceback** - Python's names for "a module could not be loaded" and "a thing has no such part"; a traceback is Python's technical listing of where an error happened.
- **late binding (closure) mistake** - a programming slip where a function written inside a loop uses the loop's LAST value instead of the value at the time it was written; the "default-argument form" `lambda e, cmd=command: cmd()` avoids it.
- **tag (of a table row)** - a named style a Treeview row carries ("complete" / "incomplete"); changing the tag's colours recolours every row that carries it. **style map** - ttk's per-state colour list (e.g. "when selected, use this colour").
- **dictionary order** - Python remembers the order in which items were first added to a collection; the client list follows that order. **NTFS** - Windows' usual disk format. **regex (regular expression)** - a text pattern the program matches file names against.

**GST rules on screen.** Several things the screens show are decided by GST rules (which return files are expected, how file names identify the return and period, the state code in a client key, which report each client gets). They are tagged **[GST RULE]**, described only, never judged; values that can change over time carry ⚠.

### 10.3 Start-up: the console window and the install offer (A-F1)

#### 10.5.8 What the user sees during and after a scan

- **During:** nothing moves. The scan runs inside the button's click, on the window's own thread, and nothing asks the window to repaint (`gui/handlers/file_handler.py:62-72`), so the window does not respond until the scan ends; on a slow network share Windows may mark it "Not Responding" (READ HIGH; the message of commit 4f84ba9 (A only (after the split)) reports a scan of 2,508 files on the real share taking about 41 seconds after a speed-up, down from a projected 11 minutes). The status texts set during the scan are never painted (10.4.2).
- **After, ≥ 1 client found:** Step 2 opens with the summary and the table filled (RAN shot 06).
- **After, no client found:** the user stays on Step 1; only the status bar says "No valid GST files found"; the warning line "⚠️ No valid GST files found" goes to the Step 3 log, which is not on screen (`gui/handlers/file_handler.py:89-91`). A folder that exists but cannot be listed (for example a share that drops between the existence check and the listing, or a folder the user may not list) also ends here, because a listing error is turned into an empty list (`utils/helpers.py:321-365`) (READ HIGH). A folder that does not exist at all is stopped earlier by the box "Source folder does not exist" (`gui/handlers/file_handler.py:126-128`). [Corrected during verification - originally "an unreachable folder", which for a path that no longer exists gives the box instead.]
- **Error boxes:** "Error" / "Please select a source folder containing GST files" (source empty) and "Error" / "Source folder does not exist" (`gui/handlers/file_handler.py:120-130`) - Scan and Re-scan are greyed under the same condition (`gui/tabs/setup_tab.py:585-591`), so these two boxes are reachable only when the checklist is behind the box: during the 350 ms before it re-checks a just-changed path, or when its remembered "exists" answer is out of date (READ HIGH; the tour called the scan function directly to see the wording) [Corrected during verification - originally said "or via Re-scan", but Re-scan is greyed exactly like Scan]; any other failure → "❌ Scan error: <error>" in the Step 3 log and box "Scan Error" with the error text (`:93-95`). A file path in the source box passes the checklist and fails here with "Not a directory: <path>" (`core/file_parser.py:154-155`).
- Files that are not recognised are only COUNTED on Step 2 (A-F9); there is no on-screen list of them (A-F9; DOCS RM20).

#### 10.7.3 What happens when the user presses Start (Step 2 "🚀 START" or Step 3 "🚀 START PROCESSING")

In this order (`gui/handlers/processing_handler.py:69-134`; RAN tours 1 and 2):

1. If a run is already active: nothing (no message).
2. Template / target checks - boxes titled "Error": "Please select both ITC and Sales template files", "Please select a target folder for organized files", "ITC template file not found", "Sales template file not found" (`gui/handlers/file_handler.py:132-151`; A-R51).
3. Nothing ticked → box "Warning" / "Please select at least one client to process".
4. Only when Step 1's "Include client name in Level 4 folder names" is ticked: client names longer than the Step 1 maximum length (fallback 10 if that is 0 or unreadable) are listed (at most 5) in a Yes/No box "Warning" - exact (RAN tour 2, limit 20): "Long client names detected (exceeding 20 chars):\n\n• GenericLongClientNamePlaceholder (32 chars)\n\nIf you continue, these client names will be used in folder names.\n\nContinue anyway?" - No stops here (A-R136).
5. The app switches to Step 3, greys out START, enables STOP, writes "🚀 ════════ PROCESSING STARTED ════════" and starts the background worker (a daemon thread, killed without clean-up if the program exits).
6. Per ticked client, in table order: folders → copies → ITC report → Sales report → organisation text file, with the log lines of 10.7.4 and the progress texts of 10.7.1 (A-R60).
7. Summary workbook, completion lines, then the box **"Processing Complete"** - "Successfully processed <p>/<t> clients\n\nFiles organized in:\n<target folder>" (RAN; called from the worker thread, RAN thread name "Thread-1 (process_files_thread)"). The same wording appears after a Stop or when clients failed (RAN tour 2: "Successfully processed 1/3 clients" after Stop). It names the target folder, not the new `Annual Statement-…` folder.
8. After OK: the new `Annual Statement-…` folder is opened in Windows File Explorer (`os.startfile`) and "📂 Opened output folder" is logged (on Linux/macOS through `xdg-open` / `open`; the success line is logged even when that fails - RAN: "sh: 1: xdg-open: not found" yet "📂 Opened output folder" appeared).
9. Workflow 'organize': "ℹ️ Workflow is 'organise only'. Open Step 4 if you also want to refresh Power Query." Workflow 'full': "🔄 Full pipeline: moving to Step 4 to extract…", the app switches to Step 4, fills its folder box, scans, and logs "✅ Step 4 ready - review the client list and press Process to refresh." Step 1's Browse, the path boxes, Scan and Re-scan, every Step 2 button (including Dry Run and Export) and all of Step 4 stay usable. #### 10.8.5 What happens when the user presses "🚀 Start Processing" (A-F21 to A-F24)

1. Clients with at least one tick are collected; none → box "No Selection" / "Please select at least one report to process" (`power_query_extractor/gui/extractor_window.py:845-861`).
2. The wait time and suffix are copied to the refresher (`:864-865`); the Processing sub-tab is selected; Start is greyed; the log is cleared; a background worker (daemon thread) starts (`:867-883`).
3. **Outside the program (Windows, pywin32, READ only):** for each ticked report Excel opens **visible and maximised**, the program brings it to the front and **types Alt+A, R, A** (Data → Refresh All in English Excel, A-R71 ⚠), waits at least about 36 seconds per report at the default 10 seconds (A-R72), closes error dialogs it finds - on ANY program's visible dialog-type window (window classes `#32770`, `NUIDialog`, `bosa_sdm_msword`) whose title contains "microsoft excel" or one of the words error, problem, cannot, failed, unable, could not, exception, invalid, missing, by clicking a button labelled OK / Close / Yes / Continue or else asking the window to close (`report_processor.py:417-525`; A-F26) - then saves and closes; then opens the copy again in a second, hidden Excel to read the cells (A-F23). If Excel could not be brought to the front, the keystrokes go to whatever window has the focus (`report_processor.py:259-276`). Inference (HIGH): the user must not type or click while a refresh runs.
4. At the end: the consolidated workbook is written into the chosen `Annual Statement-…` folder; the box **"Complete"** - "Processing complete!\n\nOpen the consolidated report?" (Yes / No) (RAN text); Yes opens it with Windows' default program (Excel) (`:968-975`). Any failure in the run → log "❌ Error: …" and box "Error" / "Processing failed: <error>" (`:957-960`).
5. Start is enabled again, the progress resets to "Ready", and the "Last Refresh Status" texts are recomputed (`:977-986`).

There is **no Stop button** in Step 4, and closing the main window during a Step 4 run gives no warning (A-R143; `gui/main_window.py:344-355`). Nothing stops Step 3 and Step 4 from running at the same time (A-R135).

### 10.11 Every message box and every file or folder picker

#### 10.11.1 How message boxes look and behave

- They are Tk message boxes (`tkinter.messagebox`). On Windows Tk shows the standard Windows box: `showerror` with the red ✕ icon and an OK button, `showwarning` with the yellow triangle and OK, `showinfo` with the blue "i" and OK, `askyesno` with a question-mark icon and Yes / No buttons (READ; how each looks on the author's PC not seen, LOW for exact look).
- Each box is **modal**: the program waits until it is answered. Two boxes are raised by the Step 3 worker thread ("Processing Complete", "Processing Error"); the worker then waits for OK, so until then the Start button stays greyed, the output folder is not opened and the Step 4 hand-over does not happen (READ `gui/handlers/processing_handler.py:498-519`; RAN: the recorder saw the thread "Thread-1 (process_files_thread)"). Raising a box from a worker thread relies on Tk passing the call to the window's own thread; it worked here (Linux, Tk 9); on the author's Windows Python not checked (MEDIUM).
- Every Step 4 box is raised on the window's own thread (`power_query_extractor/gui/extractor_window.py:952-960, 989-1010`; RAN "MainThread").
- None of the boxes names the window it belongs to, except the two install boxes (M1: the hidden start-up window; M2: the "Installing…" window); for the others Tk uses the main window and Windows decides where they appear (READ `utils/dependency_installer.py:116-117, 141-148`).
- Wording: the exact text of all 25 was seen in runs - 23 in this section's tours (recorders replaced the boxes and wrote down title, text and thread) and M17 / M18 in an earlier reader's run (GUI exp8). Their Windows look is READ only.

### 10.13 The typical user workflow, click by click

The order below is what the code expects (READ), confirmed on screen where marked (RAN tours 1-6). Variants follow.

#### 10.13.1 Main path: organise files and create reports ('organize' workflow)

1. **Start the program** from a console window in the program folder: `python main.py` (or `py main.py`, or double-click `main.py`). A black console window shows the banner and the requirements report (10.3). If a package is missing, answer the "Install missing packages?" box (M1); "Yes" installs and restarts, "No" continues only if nothing essential is missing.
2. **The main window opens on "📁 Step 1: Setup"** (1200×800, centred). If the program was used before, the four paths, the workflow, the processing mode, the include-name tick, the length and dark mode come back from the settings file, and the checklist shows ✓ / ✕ for each path (RAN: tour 4 restored every value; shot 34 shows a restored checklist, there in dark mode). Scan results are NOT remembered - Step 2 is empty at every start (RAN shot 31).
3. **Check the CHECKLIST card.** All four rows "✓" (pill "Ready - all 4 items set") is the intended state before Step 3; only the source row is needed to scan. The checklist does not itself block Step 3: Step 3's own check is weaker - both template files must exist and a target must be typed, but a target folder that does not exist yet is simply created by the run (A-R51; `gui/handlers/file_handler.py:132-151`; `core/file_organizer.py:65-69`) (READ HIGH). [Corrected during verification - originally said every row "must show ✓ … before Step 3 can succeed".]
4. **In "WHAT SHOULD THIS RUN DO?" leave "📁 Organise files & create reports" selected** (the default; the choice is saved at once).
5. **Scroll down** (wheel or scroll bar - at 1200×800 only the top 40 % of the page is visible, RAN) **to "📂 FOLDERS & TEMPLATES" and click the four "Browse…" buttons** in turn: source folder (P1), ITC template (P2), Sales template (P3), target folder (P4). Each choice is saved; typing a path instead also works but is not saved until something else saves (A-R116).
6. **In "⚙️ PROCESSING MODE" pick "🆕 Fresh Run"** (default) for a new batch - or "🔄 Re-Run" to add a new version to the latest batch (this choice is not saved). Optionally tick "Include client name in Level 4 folder names" and adjust "Max client folder name length" with the arrows.
7. **Scroll further and click "🔍  Scan Files".** The window freezes while the top level of the source folder is read (seconds; longer on a network share). When at least one client is recognised, the program jumps to **"✅ Step 2: Validation"** by itself (RAN shot 06). If nothing is recognised the user stays on Step 1 and only the status bar says "No valid GST files found".
8. **Read the "📊 SCAN SUMMARY"** (files found, recognised, unrecognised count, clients complete / with missing files).
9. **Tick the clients to process** in the table: click the "✓" column of a row, or use ↑ / ↓ and Space, or the buttons "☑️ Select All" / "☐ Clear All" / "✅ Complete Only". All rows start unticked (A-R138).
10. Optional: **scroll the table to the right** (horizontal scroll bar) to reach the "📁 Name" column and click a client's cell to add its name to its folder names (M14 / M15 may appear) (10.6.3, A-F10).
11. Optional: **click "🧪 DRY RUN"** - the program jumps to Step 3 and writes a text preview into the log (no file touched); click the "✅ Step 2: Validation" tab to come back.
12. Optional: **click "📋 EXPORT LIST"** to save the ticked clients to a `.txt` file (P5, M17).
13. **Click "🚀 START"** (Step 2) - or "🚀 START PROCESSING" on Step 3. Possible stops: M7-M10 (templates / target), M12 (nothing ticked), M13 (long names, only with the include-name tick on). Then the program jumps to **"🚀 Step 3: Processing"**: Start greys out, Stop becomes active, the bar and the "Client i of n: … | ETA: …" line move, the dark log fills (RAN shots 26, 12).
14. **Wait** (do not close the window - the box M21 appears if you try, and closing kills the run in the middle of a client). "⏹ STOP" stops after the current client.
15. **Click OK on "Processing Complete"** (M19). Windows Explorer then opens the new `Annual Statement-<DDMMYY HHMM>` folder, and the log ends with "ℹ️ Workflow is 'organise only'. Open Step 4 if you also want to refresh Power Query." (RAN tour 2).

#### 10.13.2 Continuing to Step 4 (refresh Power Query and extract)

16. **Click the "🔄 Step 4: Extract" tab.** The "Folder Path" box already holds the Step 1 target folder (unless the user typed another one there); the client list is empty and "🚀 Start Processing" is greyed (RAN shot 33).
17. **Click "🔍 Scan"** (or "📁 Browse" to pick another folder, P6, which scans at once). The newest `Annual Statement-*` folder inside that folder is used; one row per client folder appears with ITC and Sales ticks pre-ticked where the report exists, and "Last Refresh Status" (RAN shot 11). Nothing visible confirms the scan except the list itself; "Found <n> clients" is written only on the "Processing" sub-tab (10.8.6).
18. Optional: untick reports, or use "✓ Select All" / "✗ Deselect All" / "ITC Only" / "Sales Only"; change "Power Query Wait Time" (arrows, 5-60 s), "Refreshed File Suffix", or tick "Skip Refresh".
19. **Click "🚀 Start Processing".** The panel switches to its "Processing" sub-tab and the log starts. On Windows, Excel opens visibly and maximised for each report and the program types Alt+A, then R, then A into it (10.8.5; `power_query_extractor/core/report_processor.py:282-292`). [Corrected during verification - originally said "Alt, R, A"; the first keystroke is Alt+A.] **Inference (HIGH): the user must not use the mouse or keyboard until the run ends** - keystrokes go to whatever window is in front. There is no Stop button.
20. **Answer "Complete" / "Open the consolidated report?" (M24)** - "Yes" opens `PQ_Extraction_Report_<YYYYMMDD_HHMM>.xlsx` (saved inside the `Annual Statement-…` folder) in Excel. The "Last Refresh Status" texts update.
