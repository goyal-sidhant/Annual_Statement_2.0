**Plain-English terms used in this section** (first use explained here once):

- **window / dialog / message box** - a window is a framed area on screen; a dialog is a small window that asks something; a message box is a standard small dialog with an icon, a text and buttons such as OK or Yes/No. **Modal** = it blocks the rest of the program until answered.
- **Tk / Tkinter** (Python's built-in window toolkit) and **ttk** (Tk's "themed" widgets, whose colours come from a shared style table rather than from each widget). **widget** = any single on-screen element (button, label, text box, table). **theme 'clam'** = one of Tk's built-in looks (flat grey-beige).
- **tab / notebook** - a notebook is the container with clickable tab titles ("Step 1" … "Step 4"); a **sub-tab** is a tab inside a tab.
- **Treeview** - Tk's table widget (the Step 2 client table).
- **Entry** (one-line text box), **Spinbox** (number box with small up/down arrows), **Checkbutton** (tick box), **Radiobutton** (round option button, one of a group), **Text / ScrolledText** (multi-line text box, with a scroll bar), **Label** (fixed text), **LabelFrame** (a box with a title written into its border), **Canvas** (a drawing area, used here to make a page scroll), **progress bar**.
- **pack / grid / place** - three Tk ways to position widgets: *pack* stacks them top-to-bottom or side-by-side, *grid* puts them in rows and columns, *place* puts them at fixed pixel coordinates.
- **`command=` vs `.bind('<Button-1>')`** - two ways to connect a button to a function. `command=` runs on a normal click (press and release), is ignored when the button is disabled (greyed out), and can be triggered from the keyboard. `.bind('<Button-1>')` reacts to the raw left-mouse press: it still fires on a greyed-out button and cannot be reached from the keyboard.
- **tooltip** - a small yellow pop-up text that appears when the mouse rests on something.
- **status bar** - the strip at the bottom of a window that shows a one-line message.
- **worker thread** - a second line of work running beside the window so the window stays usable; **UI thread / main thread** - the one that draws the window.
- **debounce** - wait until typing pauses before re-checking.
- **hex colour** - a colour written as `#RRGGBB`, e.g. `#0078D4` (blue).
- **COM / pywin32** - Windows' way for Python to drive Microsoft Excel, and the Python package that provides it.
- **settings file** - `~/.gst_organizer_cache.json` in the user's home folder, where the program remembers paths and choices (A-F27). `~` means the user's home folder (on Windows `C:\Users\<user>`).

**GST rules on screen.** Several things the screens show are decided by GST rules (which return files are expected, how file names identify the return and period, the state code in a client key, which report each client gets). They are tagged **[GST RULE]**, described only, never judged; values that can change over time carry ⚠.

### 10.3 Start-up: the console window and the install offer (A-F1)

The user starts the program with `python main.py` (or `py main.py`, or by double-clicking `main.py`, which Windows opens with the console Python). There is no `.bat` launcher, no shortcut and no `pythonw.exe` use in A (READ; START notes). The program **needs** a console: its first line re-wraps the console output as UTF-8 (`main.py:17`), which fails when there is no console (RAN START: with `sys.stdout = None`, as `pythonw.exe` gives, the program dies with `AttributeError` before any window or log exists). (A-R127.)
