**Plain-English terms used in this appendix.**
- **test** (a small program that runs one part of the app with known inputs and checks the result); **test suite** (all of them together); **pytest** (the tool that finds and runs them).
- **collected** (how many individual tests pytest found); **passed / failed / skipped / error** (the check held / did not hold or crashed / the test chose not to run, e.g. because there is no screen / something broke while preparing or loading the test).
- **fixture** (a helper that prepares something before a test, e.g. a temporary folder or a fake Excel file); **parametrize** (one test function run several times with different inputs; each input counts as one collected test).
- **tmp_path** (a fresh throw-away folder that pytest makes for each test, under the computer's temp area).
- **monkeypatch** (temporarily replacing a real function by a fake, e.g. a fake `pip`).
- **subprocess / probe** (a test that starts a second, separate Python program, which runs a short script and reports back as text).
- **Tk root** (the main window object of Tkinter, the window toolkit A uses); **display / xvfb** (Linux needs a display server to open windows; `xvfb-run` supplies an invisible one; a Windows PC always has one).
- **COM / pywin32** (Windows' way for Python to drive Microsoft Excel / the package that provides it); none of it exists on Linux.
- **mutation check** (deliberately putting an old bug back into a scratch copy and running the tests to see whether they notice: CAUGHT = a test failed, SURVIVED = nothing noticed).
- **characterization test** (a test that records what the code does today so that later changes cannot alter it silently; it does not claim the behaviour is right).
- **bytecode / `__pycache__`** (compiled copies of Python files that Python writes into a `__pycache__` folder next to the source unless told not to, with `-B` or `PYTHONDONTWRITEBYTECODE=1`).
- **coverage** (which parts of the program a test run actually executes).
