## SECTION 1: EXECUTIVE SUMMARY

Project A is a desktop program that takes **one folder holding many clients' GST Excel files**, recognises each file **only from its name** as one of six kinds - GSTR-2B Reco, IMS Reco, GSTR-3B Export, Sales, Sales Reco and Annual Report [GST RULE] ⚠ (`utils/constants.py:13-75`; apart from an 8-byte check that the file really is an Excel file, nothing inside a client file is ever read, Section 4.1) - copies (never moves) the files into a dated folder tree per client and state (`core/file_organizer.py:71-300`), and builds for every client an **ITC report and a Sales report** from the author's own Excel templates (pre-built workbooks the program fills in) by writing folder paths and file names into each template's "Links" sheet, the sheet the template's queries read (`core/excel_handler.py:66-322, 603-713`) [Corrected during verification - originally `603-708`; the function that prepares those Links values, `prepare_template_data`, runs to its `return data` at `:713`]. In its fourth step it opens each report in Microsoft Excel, refreshes its **Power Query** (Excel's built-in data-import tool, which re-reads the client files the Links sheet points to), reads 22 configured cells [GST RULE] ⚠ (`power_query_extractor/config/cell_mappings.py:33-228`) and writes them, for all clients, into one consolidated workbook `PQ_Extraction_Report_<YYYYMMDD_HHMM>.xlsx` (`power_query_extractor/core/data_consolidator.py:20-186`).

It is built for the author's own CA/GST practice (HIGH: the author's audit method says so, `Project_Audit_FINAL.md:7`, and the code's file names and templates are those of an annual-statement job), where an annual-statement batch means sorting several downloads per client for many clients, pointing each client's report at the right files, refreshing every report and copying the key figures into one summary - work it replaces with one window of four steps, "Setup", "Validation", "Processing" and "Extract" (the tabs are created at `gui/main_window.py:131-149`; their labels "📁 Step 1: Setup", "✅ Step 2: Validation", "🚀 Step 3: Processing" and "🔄 Step 4: Extract" are set at `gui/tabs/setup_tab.py:161`, `gui/tabs/validation_tab.py:21`, `gui/tabs/processing_tab.py:20` and `gui/tabs/extract_tab.py:50`, added during verification); that office staff use it on a shared network folder is MEDIUM (the code assumes a share, and the July 2026 commit messages of `4f84ba9` and `7347383`, A only (after the split), describe runs of 2,508 and 3,030 files on the office share).

It is built with Python and uses **Tkinter** for the window, **openpyxl** (a Python library that reads and writes `.xlsx` files without Excel, but drops Power Query when it saves) for the summary and consolidated workbooks and as a fallback, and **Microsoft Excel through COM** via the **pywin32** package for writing into and refreshing the Power Query reports (`gui/main_window.py:9-10`; `core/excel_handler.py:19-33`; `power_query_extractor/core/report_processor.py:20-36`; `requirements.txt:5, 9`), so its real job needs a Windows PC with Excel and pywin32; `requirements.txt:2` says "Python 3.7 or higher required" ⚠, but the package versions that ran here need at least Python 3.8 (openpyxl 3.1.5) and 3.10 (pytest 9.1.1), and the July 2026 commit messages name a Python 3.14 on the author's PC (Section 9.4).
