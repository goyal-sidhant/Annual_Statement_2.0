# Cross-project map: project A (AnnualStatement_oldv1) against project B (AnnualStatement_oldv2)

This map pairs every feature (A-F, B-F), every business rule (A-R, B-R) and every gap (A-G, B-G) of the two old versions of the GST File Organizer, and lists every commit each project made on its own after the two lines of work split. Every comparison section and the later numbered decision list for "Annual Statement 2.0" refers to the rows below.

**The two projects.** A = `goyal-sidhant/AnnualStatement_oldv1`, branch `main`, snapshot `bf2f1dd` (27-07-2026), a Tkinter window (Tkinter is Python's built-in window toolkit) calling itself "GST File Organizer v3.0", with 288 tests. B = `goyal-sidhant/AnnualStatement_oldv2`, branch `main`, snapshot `b0e7d0e` (09-02-2026), a PyQt5 window (PyQt5 is a separate, add-on window toolkit) calling itself "v4.0", with no tests. The names mislead: A is not the older one and B is not the newer or better one. Both share their first 12 commits (`edac6a3`, 31-08-2025 … `47a1492`, 30-10-2025) and split after `47a1492`. B then made 5 commits of its own on 07-02-2026 to 09-02-2026; A made 34, two in March 2026 (documents only) and 32 in July 2026. GitHub's records say B's repository was created on 31-08-2025 and A's on 07-02-2026.

**What the map does not do.** It never says which version of a GST rule is right. A "GST rule" here is anything that decides a tax figure; which return, table, sheet or cell a figure belongs to (for example GSTR-9 Table 6J or 8D); a rate, limit or threshold; rounding; the financial year or tax period; GSTIN, PAN or state-code logic; ITC eligibility or reversal; or a due date. Such rows are tagged **[GST RULE]**; values that change over time (return and table names, template cell positions, state lists, dates) carry **⚠**. "Which works better" remarks appear only for technical behaviour (crashes, safety of Excel and files, speed, messages).

**Files that are byte-for-byte the same in both** (RAN, `git ls-tree`): `README.md`, `core/__init__.py`, `power_query_extractor/__init__.py`, `power_query_extractor/config/__init__.py`, `power_query_extractor/config/cell_mappings.py` (all extraction cell mappings), `power_query_extractor/core/__init__.py`, `power_query_extractor/gui/__init__.py`. In `utils/constants.py` only three things differ (D:utils/constants.py, RAN P:const.*): the IMS Reco file-name pattern, the three category folder names, and A's extra `WORKFLOW_MODES`; the state table, expected file types, Links cell map, processing modes, messages, safety values and GUI constants are identical.

**Relation words.** Features and rules: *same* (identical behaviour and values), *different*, *only A*, *only B*. Gaps: *same defect in both*, *only A*, *only B*; "(in part)" means the gap has several parts and only some are shared - the one-line text says which.

**Terms used throughout.** *Links sheet* - the sheet in each ITC and Sales template into which the program writes folder paths and file names for the template's queries to read. *Power Query* - Excel's data-import tool; its queries live inside the workbook and "refresh" re-runs them. *openpyxl* - a Python library that writes `.xlsx` files without Excel; it drops Power Query when it saves an existing workbook. *Run folder (Level 1)* `Annual Statement-<DDMMYY HHMM>`; *client folder (Level 2)* `<client>-<state code>`; *Version folder* `Version-<DDMMYY HHMM>`; *category folders* - the three folders inside a Version folder. *Variations* - the code's word for unrecognised or rejected files. *Date modified* (mtime) - when the system last recorded a change to a file or folder. *Thread* - a second line of work beside the window; a *daemon* thread is killed instantly when the program ends. *Signal* - Qt's message from one part of the program to another.

**At a glance** (counted by `/root/merge-scratch/run/MAP/scripts/coverage.py`, output at the end). Feature map: 34 rows - 2 *same* (cell extraction A-F23 / B-F22; error-dialog closing A-F26 / B-F26), 28 *different*, 2 *only A* (live setup checklist A-F4; workflow choice A-F5), 2 *only B* (settings import B-F2; run history B-F17). Rule map: 165 rows - 81 *same*, 71 *different*, 12 *only A*, 1 *only B* (B-R118). The shared business core (file-name patterns other than IMS Reco, state codes, completeness, folder keys, copying, Links cells, refresh, extraction cells, consolidated look-up) is almost entirely *same*; the differences sit in file discovery, name cleaning, folder names, the screens, settings, start-up and Step 4's choice of folders. Eleven GST-rule pairs are not *same*; they are set out with worked examples in 2.1. Gap map: 98 rows - 73 *same defect in both* (some only in part), 16 *only A*, 9 *only B*. In particular the 9-column consolidated mismatch, the unconfirmable refresh, the Links-cell defects, Resume, and the take-over of the user's Excel are in both.
