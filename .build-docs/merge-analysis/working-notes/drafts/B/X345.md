## APPENDIX X3: TEST SUITE

### X3.0 How to read this appendix

- **Test** (in this appendix): a small program kept in the project that runs part of the real code on known inputs and checks the result automatically, so that a later change which breaks something is noticed at once. **Test suite**: all such programs together. **pytest**: the usual Python tool that finds and runs them. **Regression**: something that worked before and stopped working after a later change.
- **Commit**: one saved step in the project's history (identified by a short code such as `c258047`). **git**: the tool that keeps that history. **PyQt5** and **Tkinter**: the two window toolkits (libraries that draw windows, buttons and lists); B's current program uses PyQt5, the older program described by the README used Tkinter. **openpyxl**: a Python add-on that reads and writes Excel files without Excel itself. **Power Query**: Excel's built-in tool that pulls data from other files into a workbook when it is "refreshed".
- **Pure Python part**: code that needs neither Windows nor Excel (for example file-name recognition, folder naming, the consolidated workbook written with openpyxl). Such parts can be tested on any computer. **COM part**: code that drives the real Microsoft Excel through Windows (COM = Windows' mechanism by which one program remote-controls another; pywin32 = the Python add-on that provides it). Such parts can only be tested on a Windows PC with Excel, or partly with **stand-ins** (fake modules that imitate Excel's replies, so that only the order of the program's own steps is checked).
- Every statement says how it was established: **READ** (by reading code or `git` output) or **RAN** (by executing something). "(me)" = done by this task (scripts and outputs in `/root/merge-scratch/run/B-X345/`); a note abbreviation in brackets (for example "(DO)") = done by the reader agent whose notes are named in X6.0; "(verify)" = re-done during the verification pass of this appendix (scripts and outputs in `/root/merge-scratch/run/VERIFY-B-X345/`, on a fresh copy of the code, `python -B`, no file written into the copy). Confidence words for inferences: HIGH / MEDIUM / LOW. Places changed by the verification pass carry the note `[Corrected during verification - …]`.
- Commits: the 12 commits `edac6a3` … `47a1492` are marked [shared - before the split on 30-10-2025]; `c258047`, `a62d3cc`, `c21f788`, `7e09e5c`, `b0e7d0e` are marked [B only (after the split)]. Where a hash appears in a table cell without its tag (to keep the tables readable), the tag is the one fixed here: `edac6a3`, `cbfa4a5`, `6237597`, `9c56a1c`, `d674386`, `5ea77c2`, `1cb878b`, `01862a0`, `1c48722`, `4c42758`, `bd176bf`, `47a1492` = shared - before the split on 30-10-2025; `c258047`, `a62d3cc`, `c21f788`, `7e09e5c`, `b0e7d0e` = B only (after the split). Feature IDs (B-F…), rule IDs (B-R…) are from the registry; gap IDs (B-G…) are from Section 7 (gap register, Section 7.10).
