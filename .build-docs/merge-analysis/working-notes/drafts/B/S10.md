## SECTION 10: UI/INTERFACE DOCUMENTATION

Project B has **one window**, titled "GST File Organizer v4.0", built with **PyQt5** (a Python add-on that draws Windows-style windows using the Qt toolkit). Everything the user does happens on the four **tabs** (pages you switch between by clicking their labels at the top) of that window - "Step 1: Setup", "Step 2: Validation", "Step 3: Processing" and "Step 4: Extract & Refresh" - plus small pop-up **message boxes** and the standard Windows **file / folder pickers**. Two outside programs also appear on screen because of B: **Windows Explorer**, opened on the output folder after processing (Windows only), and **Microsoft Excel**, which Step 4 opens visibly, maximised, and types keystrokes into (B-F19). There is no other user interface: no command-line options, no settings dialog, no "About" box, no confirmation dialogs.

This section describes every screen, control and message as the code at the snapshot (b0e7d0e, 09-02-2026) builds them, how the screens look, how they behave, and the typical sequence of clicks. All the screen code was written in B's own commits (c258047, a62d3cc, c21f788, 7e09e5c, b0e7d0e - all **B only (after the split)**); the shared commits (edac6a3 ... 47a1492, **shared - before the split on 30-10-2025**) had two different Tkinter programs, summarised in 10.13.

> **The UI findings that matter most (details and evidence below)**
> 1. **No window at all without pywin32.** On a PC without the pywin32 add-on the program stops before any window appears and prints advice in the console that would not fix it (10.2; B-F1, B-R124). RAN.
> 2. **Three of the four "Browse" buttons on Step 1 are invisible** (white on white). They still work if clicked blindly; the user is otherwise forced to type or paste paths (10.4; B-F3). RAN (pixels: 100 % white).
> 3. **Step 4 never shows on screen why a report failed** - only "Result: ITC: FAIL, Sales: FAIL". The reason goes only to the program log file. Yet after a fully failed run the list shows every version as "Refreshed (date)" in green and the Step 4 tab gets a green "done" dot (10.7; B-F18, B-F24, B-F29). RAN.
> 4. **Nothing is locked while a job runs.** During processing, Step 2 "START", "DRY RUN", "SCAN FILES" and Step 4 "Start Extraction" all stay clickable; processing and extraction (both driving Excel) can run at the same time; closing the window during a run is accepted at once with no question (10.9; B-F34, B-R111, B-R138). RAN (START, SCAN FILES and Start Extraction checked during a run; closing by MW e11) + READ (no code ever disables the others).

> 6. **Dark mode is only partly applied**: Steps 1 and 2 stay white, and the status lines of Steps 3 and 4 become dark grey text on a black background (practically unreadable) (10.10; B-F28). RAN (pixels and screenshots).
> 7. **"EXPORT LIST" does nothing** (no action is connected to it) (10.5; B-F10). RAN.

**Plain-English terms used in this section**

- *Widget*: any visible piece of a window - a button, a text box, a list, a label.
- *Text box* (Qt "line edit"): a one-line box the user can type into. *Spin box*: a number box with small up/down arrows. *Tick box* (check box): a square the user ticks or unticks. *Radio buttons*: a group of round buttons of which exactly one is chosen.
- *Table / tree view*: a list with columns; a *tree* has rows that open into child rows (Step 4: client → version).
- *Message box*: a small pop-up window with a message and an OK button; it is *modal* - the rest of the window cannot be used until it is closed.
- *Status bar*: the thin line of text along the bottom edge of the window.
- *Splitter*: an invisible divider between two side-by-side panels that the user can drag to make one wider. *Scroll area*: a panel with its own scroll bar when its content is taller than the space.
- *Stylesheet (QSS)*: text, similar to a web page's CSS, that sets colours, fonts, borders and sizes. B sets one stylesheet for the whole program (light or dark) and many small ones on individual widgets; a widget's own stylesheet wins over the program-wide one.
- *objectName*: a label given to a widget so a stylesheet rule can target it (for example a button named "danger" gets the red style).
- *Signal / slot*: Qt's message system - clicking a button "emits a signal", and whatever function is "connected" to it runs.
- *Worker thread*: a second line of work inside the program, so the window keeps responding while a long job runs.
- *HTML*: the markup language of web pages; B's on-screen logs insert each line as a small piece of HTML.

### 10.2 Starting the program - what the user sees first

**How it is started.** README.md:112 tells the user to type `python main.py` in a console; README.md:166-169 tells them to type `python launch_extractor.py` "after main processing". There is no `.bat` launcher, no desktop shortcut and no use of `pythonw` (the console-less Python) anywhere in the repository (READ: `/root/merge-scratch/audit/B_files.txt`). `main.py:41-42` names the application "GST File Organizer", version "4.0" (these names are not shown anywhere on screen; the window title is set separately at `gui/pyqt_main_window.py:71`). `launch_extractor.py` builds the same window and switches it to the fourth tab before showing it (`launch_extractor.py:17-18`) - RAN e5: title "GST File Organizer v4.0", tab shown "Step 4: Extract && Refresh" (index 3).

```text
<date time> - root - ERROR - Import Error: No module named 'pythoncom'

 Missing module: No module named 'pythoncom'

Please install required packages:
  pip install PyQt5 openpyxl
```

The program then ends with exit code 1 (`main.py:49-54`). The advice would not help, because the missing piece is pywin32, which `requirements.txt:13-14` leaves commented out (B-R124). Through `launch_extractor.py` the console shows only "Failed to launch: <error>" (`launch_extractor.py:22-24`, READ). **First view.** RAN (e1, e6): the window always opens on **Step 1** at **1400 × 900** pixels (minimum 1200 × 800), status bar "Ready", no coloured dots on the tabs, "RE-SCAN" greyed out - even when the previous session ended on Step 4 and `session_state.json` says `"active_tab": 3` (that file is written on close but never read, B-R117). (RAN e1).

**Comparison with the author's Standard 13 (facts only).** Standard 13 (rebuild_pipeline_FINAL.md:900-1061) expects a `Run [App Name].bat` launcher that starts `pythonw.exe` with no console from a shared runtime, a `sys.excepthook` and `threading.excepthook` that write the error to a file under `%LOCALAPPDATA%\[App Name]\` and show a plain-English message box, and settings and logs under `%LOCALAPPDATA%\[App Name]\`. **Layout approach.** Every screen is built in code (no designer files), with Qt **layout managers** - invisible arrangers that stack widgets in rows and columns and stretch them with the window - so nothing has a fixed pixel position. Steps 1 and 2 use a two-column draggable splitter with a scrolling left column; Steps 3 and 4 use a single column whose log stretches to fill the height. Margins are 20 px (Steps 1-2 outer), 12 px (Steps 3-4), spacing 8-12 px. Sections are drawn as "cards" (`ColoredSection`, `CollapsibleCard`) or framed group boxes (Step 4). The window cannot be made smaller than 1200 × 800 (`gui/pyqt_main_window.py:72`); at that size Step 1 shows less (scroll), and Step 2's left column overflows sideways and needs a horizontal scroll bar (RAN e1 `shots/e1_tab1_min.png`).

**Three styling layers.** (1) One program-wide stylesheet, light (`gui/theme/theme_manager.py:25-199`) or dark (`:201-405`), set on the whole application by `apply_theme` (`:414-419`) at start (`gui/pyqt_main_window.py:66`) and on View > Dark Mode (`:596`). (2) Many small stylesheets typed into the views for individual widgets (almost every coloured element). (3) Five named button styles in the program-wide sheet - "primary" (blue), "success" (green), "warning" (orange), "danger" (red), "info" (teal; no widget uses it, B-R132). A widget's own or its parent's stylesheet wins over the program-wide one, which explains most styling defects below.

### 10.11 The typical user workflow (what the user clicks, in order)

This is the sequence the screens are designed for, as traced end to end in RAN e2 (placeholders) plus the Windows-only parts by READ. Points where the screen does not help the user are marked ⚑.

**Before starting (outside the program).** The client files must be in one folder (sub-folders are ignored) and named exactly as the patterns on the Step 1 help card (**[GST RULE]** ⚠ B-R5 to B-R11); the ITC and Sales templates must exist (with their "Links" sheet, B-R53). ⚑ The program does not say so, but on Windows it is safer to close Excel first: Step 3 takes over an Excel the user already has open, hides its windows and closes it at the end of each report (B-R96), and Step 4 types keystrokes into Excel (B-R67).

1. **Start the program**: open a console in the program folder and type `python main.py`. The window opens on "Step 1: Setup", with the last saved paths already filled in. (⚑ Without pywin32 no window opens - 10.2.)
2. **Source folder**: type or paste the folder path into the first box. ⚑ The "Browse" button is invisible; clicking the blank space just right of the box opens the picker "Select Source Folder".
3. **Templates**: type or paste the ITC template path and the Sales template path (or click the blank space right of each box for the pickers "Select ITC Template" / "Select Sales Template").
4. **Target folder**: click the red **BROWSE** and choose the output folder in "Select Target Folder" (or type it).
5. **Mode and options**: keep **Fresh** (default) for a first run, or choose Re-Run / Resume (⚑ both just add a new Version folder in the most recently changed run folder - 10.4). Optionally tick "Include client name in brackets for Level 4 folders" and set "Max length" (⚑ the Max length is applied even when greyed out).
6. **Scan**: scroll the left column down and click **SCAN FILES** (⚑ below the visible part at the default size). The help cards fold away, the SCAN LOG fills with one line per file and the results, and the window jumps to "Step 2: Validation"; Step 1 gets a green dot, Step 2 an orange one; the status bar reads "Scan complete: <n> clients, <m> files, <size>".
7. **Review** on Step 2: read the SCAN SUMMARY; look at the colours in the client table (green complete, orange missing, red-orange other - ⚑ the instructions mention only two colours); ⚑ the missing and duplicate counts are numbers only - which types are missing is not shown; ⚑ the problem files counted as "Variations" are not listed anywhere.
8. **Choose clients**: every client is already ticked. Untick the ones not wanted, or use **Clear All** and tick some, or **Complete Only**.
9. *(Optional)* **DRY RUN**: the window jumps to Step 3 and lists what would be copied, and "Would create: ITC Report" / "Would create: Sales Report" for every client. Click the "Step 2: Validation" tab to go back.
10. **Start**: click **START** on Step 2 (⚑ the instructions say "Start Processing", which is the Step 3 button - both do the same). If a template or the target is missing, a "Warning" box names it; fix it on Step 1 and click START again. The window moves to "Step 3: Processing".
11. **Watch** Step 3: the status line shows "Client <i>/<N>: <client> | ETA: ...", the green bar fills client by client, and the log lists each step. **Stop** halts before the next client (⚑ no feedback; the run still ends with "Processing Complete").
12. **Finish processing**: the box "Processing Complete - Successfully processed <k>/<N> clients ... Files organized in: <target>" appears; click **OK**. The window moves to "Step 4: Extract & Refresh" (Step 3 dot green, Step 4 orange) and, on Windows, Explorer opens the new "Annual Statement-<DDMMYY HHMM>" folder. (⚑ "Successfully processed" also counts clients whose reports failed - read the log.)
13. **Choose reports** on Step 4: the list shows the client folders of one run folder ("Source: Annual Statement-...") with every square empty. Tick ITC and/or Sales per version, or click **ITC Only**, **Sales Only** or **Select All**. (⚑ The run folder shown is the one whose name sorts last, which is not always the newest - 10.7.) Optionally change the wait time, the file suffix (⚑ keep "\_Refreshed" in it) or tick "Skip refresh".
14. **Start Extraction**: click it. For each ticked report, Excel opens maximised, the refresh keystrokes are typed, the program waits, saves, and then reads the cells in a hidden Excel. ⚑ **Do not touch the keyboard or mouse** until the status says "Extraction complete" (about 39 s per report at the default wait, plus Excel start-up; B-R68).
15. **Finish extraction**: the status bar and status line say "Extraction complete"; the Step 4 dot turns green; the list is rebuilt (squares empty again) with "Refreshed (date)" against each version. ⚑ No box appears and failures are only visible as red "Result: ... FAIL" lines - and the reasons are not on screen at all. The consolidated workbook "PQ\_Extraction\_Report\_<YYYYMMDD\_HHMM>.xlsx" and "Extraction\_Log\_<YYYYMMDD\_HHMM>.txt" are in the run folder; ⚑ there is no button to open them - the user goes to the folder in Explorer.
16. **Close**: File > Exit or the window's close button. Settings are saved automatically (⚑ also if a job is still running - it is cut off without a question).

**Common variations.**

- **Extraction on another day**: run `python launch_extractor.py` (or `python main.py` and click the Step 4 tab). Step 4 is filled at start-up from the last *saved* target folder; continue at step 13.
- **After renaming files**: click **RE-SCAN** (identical to SCAN FILES) and continue at step 7. ⚑ If the Source box is changed after a scan without scanning again, START processes the old scan's files (B-R133).
- **Re-extracting without refreshing again**: tick "Skip refresh (use existing refreshed files)" before Start Extraction (works only with the default suffix, B-F21).
- **Saving the settings without scanning**: File > Save Settings (status "Settings saved").
- **Dark mode**: View > Dark Mode (partial, 10.10).
