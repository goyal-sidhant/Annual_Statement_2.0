**Plain-English terms used in this appendix.**

- **Workbook / template**: `.xlsx` is a normal Excel workbook, `.xlsm` its macro-enabled version, `.xltx` / `.xltm` Excel templates. All are ZIP files holding XML "parts".
- **Power Query** (Excel's built-in data-import tool, "Get & Transform"). Its queries live inside the workbook in a hidden part `customXml/item*.xml` containing an element called **DataMashup**, with connection records in `xl/connections.xml`. **Refresh** = re-running the queries so the workbook reads its source files again.
- **openpyxl** (a Python library that reads and writes `.xlsx` files without Excel). When it **saves** a workbook it rebuilds the file from what it understands and drops the Power Query parts; reading is harmless (Standard 12 table row at `rebuild_pipeline_FINAL.md:827`).
- **COM** (Component Object Model: Windows' way for one program to remote-control another; here Python drives Microsoft Excel). **pywin32** provides it to Python (`win32com`, `pythoncom`) together with window functions (`win32gui`, `win32api`, `win32con`).
- **GetActiveObject / Dispatch / DispatchEx** (three ways for Python to get an Excel): `GetActiveObject` grabs the Excel that is already running (normally the user's own); `Dispatch` asks Windows for "an Excel" and may connect to one already running; `DispatchEx` always starts a separate one. Standard 12 requires `DispatchEx`.
- **Visible / DisplayAlerts / ScreenUpdating / WindowState** (Excel settings: is its window shown; does it show prompts such as "Save changes?"; does it repaint the screen; is its window maximised). **Quit()** closes that whole Excel, with every workbook open in it.
- **RefreshAll / BackgroundQuery / CalculateUntilAsyncQueriesDone / Refreshing / RefreshDate** (the COM calls and properties Standard 12 names for a safe refresh: switch off background refresh on each connection, refresh everything, wait until every query has finished, check none is still refreshing, never trust the refresh date).
- **WScript.Shell / AppActivate / SendKeys** (a Windows scripting object; `AppActivate(title)` asks Windows to bring forward a window with that title; `SendKeys` types keystrokes into **whichever window has the keyboard focus**, as if a person pressed them). **Ribbon key tips** (Excel's Alt-key shortcuts: Alt, A opens the Data tab; R, A = Refresh All).
- **win32gui EnumWindows / BM_CLICK / WM_CLOSE** (list every top-level window on the desktop; "click this button"; "please close this window").
- **Thread / worker thread** (a second line of work beside the window so the window does not freeze; B uses Qt's **QThread**). **CoInitialize / CoUninitialize** (calls a worker thread must make before and after using COM).
- **`finally` block** (code Python runs at the end of a `try`, whether or not an error happened; used for clean-up).
- **8.3 short path** (an old DOS-style short alias of a long path). **`\\?\` prefix** (a Windows prefix that lifts the 260-character path limit for programs that support it). **UNC path** (a network path `\\server\share\...`).
- **glob** (a wildcard file search such as `ITC_Report_*.xlsx`). **mtime** (a file's or folder's "date modified").

**Thread names used below** (all READ, and RAN in E2E where the fake records the Python thread name): **Main** = the window's own thread ("MainThread"); **SW** = the Step 1 scan worker, a QThread started at `gui/controllers/scan_controller.py:65-80`; **PW** = the Step 3 processing worker, a QThread started at `gui/controllers/processing_controller.py:265-279` (in E2E it appeared as "Dummy-2"); **EW** = the Step 4 extraction worker, a QThread started at `gui/controllers/extraction_controller.py:148-165` (in E2E "Dummy-3").

### X2.2 Input files and file-name patterns

#### X2.2.1 Which files are looked at (B-R1 to B-R4)

- Only the **top level** of the chosen source folder; sub-folders are ignored without a message (`utils/helpers.py:249-266`, non-recursive glob; B-G46).
- Extensions searched, in this order: `*.xlsx`, `*.xls`, `*.xlsm` (`:255-257`); names starting with `~$` (Excel's lock files) dropped (`:259-260`); the rest sorted by full path (`:262`). Any listing error → empty list → "No Excel files found" (`:264-266`). Other extensions (`.csv`, `.xlsb`, `.pdf`, …) are ignored silently and counted nowhere (RAN E2E: `notes.csv`).
- Letter case of the extension: on Linux the search is case-sensitive - RAN (L): of `GSTR3B-ClientA-Delhi-Apr.XLSX`, `GSTR3B-ClientA-Delhi-May.xlsx`, `~$GSTR3B-ClientA-Delhi-May.xlsx` and `sub/GSTR3B-ClientA-Delhi-Jun.xlsx`, only the `May.xlsx` file was returned (upper-case extension, lock file and sub-folder all left out); on Windows Python's `Path.glob` ignores case by default, so the `.XLSX` file would be found (HIGH, Python behaviour; not runnable here). The **name patterns** below ignore case on every system (RAN L: `gstr3b-clienta-delhi-apr.XLSX` recognised).
- Per file (`core/file_parser.py:171-256`): `stat()` failure → skipped, log warning only; size < 1024 bytes → problem file "File too small to be valid Excel"; first 8 bytes not `PK\x03\x04` or `\xd0\xcf\x11\xe0` → "Invalid or corrupted Excel file"; unreadable → "Cannot read file: <error>"; then the name is matched against the patterns. Problem files are kept in a list (`variations`) that is never shown; only their number reaches the screen (B-F9, B-G20). The **content** of an input file is never read by Python beyond those 8 bytes - only the templates' queries read it.

#### X2.2.4 How a file becomes a client; state codes [GST RULE] ⚠

See B-G16.
- **State codes** (`utils/constants.py:234-275`, look-up `utils/helpers.py:485-511`) ⚠ - 39 lower-case names, 36 distinct two-letter codes: andhra pradesh AP; arunachal pradesh AR; assam AS; bihar BR; chhattisgarh CG; goa GA; gujarat GJ; haryana HR; himachal pradesh HP; jharkhand JH; karnataka KA; kerala KL; madhya pradesh MP; maharashtra MH; manipur MN; meghalaya ML; mizoram MZ; nagaland NL; odisha OD; orissa OD; punjab PB; rajasthan RJ; sikkim SK; tamil nadu TN; telangana TS; tripura TR; uttar pradesh UP; uttarakhand UK; west bengal WB; andaman and nicobar islands AN; chandigarh CH; dadra and nagar haveli and daman and diu DD; delhi DL; national capital territory of delhi DL; jammu and kashmir JK; ladakh LA; lakshadweep LD; puducherry PY; pondicherry PY. These are letter abbreviations, not the numeric GSTIN state codes; B has no GSTIN or PAN logic.
- **Unknown state**: two or more words → first letters of the first two words ("New Delhi" → ND); one word → the first three characters upper-cased ("Tamilnadu" → TAM; "DL" → DL) (RAN L). Each fallback writes a warning to the log.

#### X2.2.5 Which files a client is expected to have [GST RULE] ⚠

`EXPECTED_FILE_TYPES` (`utils/constants.py:68-75`): GSTR-2B Reco, IMS Reco, GSTR-3B Export, Sales, Sales Reco, Annual Report. Status (`core/file_parser.py:280-314`): "Complete" when none is missing and no type other than GSTR-3B Export has two or more files; "Missing <n> files" (n = number of missing types); otherwise "Has duplicates". GSTR-3B Export may have any number of files ("monthly filings - unlimited", `:294-296`); the number of months and their years are not checked. Completeness % = types found ÷ 6 × 100, one decimal.
