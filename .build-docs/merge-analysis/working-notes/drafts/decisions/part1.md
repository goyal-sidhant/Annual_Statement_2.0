## Part 1 - Same job, done differently

Both old tools do every job in this part, but each does it its own way. None of the differences below is a GST rule. Where a job also holds a GST rule, that piece is answered in Part 2, and the item says so. Every item has one recommendation. You can answer "A", "B", "Agree" (meaning: take the recommendation), "Drop", "Defer", "Not sure yet", or a short sentence of your own.

**Words used in Part 1** (each is explained once here):

- **A / B.** A = `AnnualStatement_oldv1` at `bf2f1dd` (last change 27-07-2026; Tkinter window; 288 tests). B = `AnnualStatement_oldv2` at `b0e7d0e` (last change 09-02-2026; PyQt5 window, "v4.0"; no tests). The names mislead: A is not the older tool, and B is not the newer or better one. Tkinter ("Tk") is Python's built-in window kit; PyQt5 ("Qt") is an add-on one. Which kit the new tool uses is Part 8.
- **Tests.** Small programs that check the code automatically and fail when its behaviour changes.
- **Commit.** One saved change in a project's history, shown by a short code such as `33d0baf`, with a date and a message.
- **RAN / READ.** RAN = checked by running the old code on made-up inputs. READ = checked by reading the code. HIGH / MEDIUM / LOW = how sure a conclusion is that could not be run here.
- **Comparison §n.** Section n of `MERGE_COMPARISON.md`, which holds the full detail. "Row 4A-n / 4B-n" means a fix made only in A or only in B (comparison §4). A-F# / B-F# are features, A-R# / B-R# are rules, and A-G# / B-G# are gaps, as numbered in the two audits.
- **pywin32 and COM.** COM is Windows' way for one program to control another. pywin32 is the add-on that lets Python control Excel that way.
- **Power Query.** Excel's data-import tool inside your ITC and Sales templates. "Refresh" means re-running it.
- **openpyxl.** A Python library that writes Excel files without Excel. It drops Power Query, and drawn shapes such as text boxes and buttons, when it saves a workbook (Standard 12; RAN on both projects' openpyxl route; whether your templates hold shapes is not known).
- **Links sheet.** The sheet in each template into which Step 3 writes folder paths and file names, for the template's queries to read.
- **Fresh / Re-Run / Resume.** The three processing modes of Step 3: Fresh starts a new batch, Re-Run adds a new version inside the latest batch, and Resume continues an interrupted run.
- **Batch folder.** `Annual Statement-<DDMMYY HHMM>`, one per Fresh run. Inside it, a **client folder** `<client>-<state code>`, and inside that a **Version folder** `Version-<DDMMYY HHMM>`, one per run. Inside each Version folder sit three **category folders**, one each for the GSTR-3B, ITC and Sales files (their names are a Part 2 item).
- **Network share.** The folder on the office server.
- **Standards 12 and 13.** Your own rules in the CLAUDE.md copy (`rebuild_pipeline_FINAL.md`). Standard 12 covers libraries and "Excel through COM" (lines 817-898). Standard 13 covers how users start an app (lines 900-1061).
- **Console.** The black text window. **pythonw** is the Python that runs with no console, and your Standard 13 starts apps that way.
- **Background worker.** A second line of work that runs beside the window, so the window does not freeze. **Signals** are Qt's safe way for such a worker to pass messages to the window.
- **Date modified.** The time the computer last recorded a change in a file or folder.
- **Variation.** The code's word for a file the scan could not use.

### P1-1. Start-up checks when an add-on is missing                    Part 1 · refs A-F1, B-F1, A-R64, A-R96, A-R124, A-R125, A-R127, A-R128, B-R97, B-R124, B-R125, A-G7, A-G22, A-G53, A-G59, B-G32, B-G34
What this is about: Before the window opens, the tool should check that the add-ons it needs are present, above all pywin32. Example: during the GSTR-9 season a new article assistant's PC is set up without pywin32. The tool must say so plainly. It must not build ITC and Sales reports that have silently lost their Power Query.
A's way: A prints a report of each add-on (A:main.py:66-73). If anything is missing, it first offers a Yes/No box to install it with pip (Python's own installer). "Yes" installs the whole package list, the test tool included, and restarts the program (A:main.py:78-95). If you say "No", on Windows it refuses to start without pywin32 and gives the reason: reports would lose Power Query (A:utils/requirements_check.py:45-60; A:main.py:97-102). Off Windows, after the same offer at every start, A opens anyway: Step 3 builds reports with openpyxl, losing their Power Query (A-G7), and Step 4 refuses each report with a clear message (A:power_query_extractor/core/report_processor.py:20-36, 66-77). Started without a console, A dies at once (A:main.py:17). Every start creates `logs` and `temp` folders inside the program folder (A:main.py:29-43).
B's way: B checks nothing. Without pywin32 its window cannot open at all, on any PC, because pywin32 is loaded with no fallback (B:power_query_extractor/core/report_processor.py:11-15, reached through B:gui/controllers/extraction_controller.py:10). Its advice, "pip install PyQt5 openpyxl", does not fix the problem (B:main.py:49-54), and B:requirements.txt:13-14 lists pywin32 only as a comment. B does survive a start without a console (B:main.py:12-13), and it creates no folders in the program folder (both tools write their log file, `gst_organizer.log`, into whatever folder they were started from).
Evidence: RAN (comparison §3, check C3-1, re-run independently): B's window code fails with "No module named 'pythoncom'", while A's loads. A's checks came in `f363946`, `be6418c` and `a5ad487` (26-07-2026) and are covered by 32 tests. A's check only looks for pywin32's files without loading them, so a damaged pywin32 passes it, and the reports are then built without Excel and lose their Power Query (A-G7, RAN). Part 8 settles the start-up method by Standard 13: a double-click launcher, and "Nothing is installed on users' PCs" (`rebuild_pipeline_FINAL.md:924`), which rules out A's install offer (also asked in Part 3). RAN (comparison §4, rows 4B-5 and 4B-6): with no console, A stopped with an error and B ran on; A added `logs` and `temp` to the program folder, B added nothing. Comparison §3 row 1; §5 Category 15.
Recommendation: A's add-on check and its clear refusal on Windows, without the install offer, plus B's console-safe start that creates no folders in the program folder. Only A tells the user exactly what is missing and keeps reports from losing Power Query, and B's start is the one that survives Standard 13's no-console launch.
